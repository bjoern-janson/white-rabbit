## Governing causal rule

> **MATCH common/background causes. MEASURE treatment consequences. CUSTODY provenance or representation facts that require preservation but not equality.**

The rule is causal, not lexical.

For every quantity `d`, classification asks:

```text
Q1. Can d differ because the intended treatment content changed?
Q2. Can d independently affect the Gate 7 outcome if it differs for a
    reason other than treatment?
Q3. Would forcing d equal block or condition away part of the intended
    treatment pathway?
```

Classification follows those answers:

```text
MATCH:
    d is a common/background cause, is not constituted by treatment,
    and equality does not remove the treatment pathway.

MEASURE:
    d is an executor-observed treatment consequence, mediator, outcome,
    or downstream work/cost quantity whose equality could remove part
    of the realized treatment pathway.

CUSTODY:
    d is a source/rendered representation fact whose exact value and
    provenance must be preserved, but equality is not required by Theta_G7.

NOT_RELEVANT:
    d has no defensible role in this local comparison.
```

No mandatory variable is classified from historical feasibility.

## Prospective causal decomposition

```text
Z = treatment content {neutral, C_improve}
S = common/background executor conditions
P = executor realization of the supplied content
Y = executor-observed consequences, including generated work

S -> P
S -> Y
Z -> P -> Y
Z ------> Y
```

A descendant of `Z` is not automatically a confound. When a quantity is generated by changing `Z` under the same executor conditions, forcing that quantity equal can replace the total realized content-effect question with a controlled direct-effect-style question.

This decomposition guides classification. It does not establish formal causal identification.

## Critical adjudication: prompt-token burden

Frozen result:

```text
PROMPT_TOKEN_BURDEN_IS_MEASURED_NOT_MATCHED
```

Under common model, tokenizer, chat template, runtime, request structure, and instructional form:

```text
Z -> executor realization -> N_prompt
```

The neutral and `C_improve` contents must differ semantically. Their executor tokenizations may therefore differ as a consequence of the intended intervention. Requiring `N_prompt` equality would constrain the mediator and change the question.

The two estimands are distinct:

```text
total realized content effect:
    effect of changing content under matched form and executor,
    including consequences of how that content is realized by the executor

content effect at fixed prompt-token burden:
    effect of changing content while additionally conditioning on or
    intervening to equalize prompt-token burden
```

The frozen `Theta_G7` specifies the first. It does not include a fixed-prompt-token-burden condition.

Therefore:

```text
N_prompt = MEASURE
old exact-token-match requirement required by frozen Theta_G7 = NO
```

The historical exact-token-match artifacts remain valid records of what was previously constituted and measured. This new specification does not delete or rewrite them. Any prospective supersession in an executable assay requires a separate constituted transition.

This classification would be unchanged if all historical token measurements were hidden: `YES`.

## Target token position

Structural target position and executor absolute token index are different quantities.

Structural target position is matched through:

```text
same message role
same prelude-before-target ordering
same separator
same target
same conversational position
```

The absolute target-start token index is produced after the common tokenizer/template realizes the differing content. If it differs only because the treatment content tokenizes differently, it is a descendant of `Z` through `P`.

Frozen classification:

```text
structural target position = MATCH
absolute target-start token index = MEASURE
```

Forcing the absolute index equal would reintroduce fixed prompt-token burden through another name. This classification would be unchanged with historical token measurements hidden: `YES`.

## Cold initial state and execution-time reuse

Initial computational state is not treatment content. Gate 7 therefore retains the independently cold run doctrine:

```text
fresh backend process per observation
fresh recorder session per observation
no prior measured request
no retained pre-request slot/KV/cache state
common startup/runtime protocol
```

Frozen classifications:

```text
initial backend state = MATCH
retained KV/cache state before request = MATCH
execution-time cache/reuse fields = MEASURE, if exposed
```

Post-request or in-request reuse may be induced by the executor realization of treatment content. Such fields are not required to be equal. `graphs_reused`, `f_sim_best`, `f_keep`, and any explicit cached-token field remain literal measurements with no invented cached-token derivation.

This classification would be unchanged with historical token measurements hidden: `YES`.

## Prompt headroom and admissibility

Context-window capacity and generation budget are matched background conditions. Realized prompt/context headroom is measured because it depends on executor realization.

A difference in headroom is not automatically a confound. If a context limit prevents the frozen request or generation budget from being validly realized, that observation is inadmissible under the existing execution doctrine; it is not repaired by reclassifying headroom as `MATCH`.

No headroom value or threshold is measured or constituted here.

## Work ledgers

Three work/economic quantities remain strictly distinct:

```text
Delta W_gen
    = N_generated^C - N_generated^B

Delta W_run
    = difference in directly measured whole-invocation executor work/cost,
      including prompt processing and generation where actually measured

Delta C_H
    = whole-horizon White Rabbit lifecycle economics,
      including acquisition, reuse, persistence, and amortization
```

```text
Delta W_gen != Delta W_run != Delta C_H
```

Gate 7's frozen primary local work currency remains:

```text
W_gen := N_generated
```

If prompt burden differs:

```text
it does not by itself block the total realized-content comparison on N_generated;
it must be measured and reported;
it blocks any claim that prompt-token burden was held fixed;
it prevents Delta W_gen alone from establishing lower whole-invocation work;
it does not authorize a Delta W_run claim without direct whole-run evidence;
it does not authorize any Delta C_H, reuse, amortization, or lifecycle claim.
```

Timing fields remain secondary literal measurements. No FLOPs, energy, hidden reasoning effort, or hidden internal computation may be inferred from them.
